# EBT Target Map

Target-area datasets and editing tools for [EBT Dot Safari](https://github.com/ShortOkapi/ebt-dot-safari), covering the curated Euro-use map.

[Open EBT Target Map](https://shortokapi.github.io/ebt-target-map)

## Project Architecture

The tool is built as a static, single-page web application integrated with a Node.js GitHub Actions worker, strictly adhering to DRY principles.

*   **`core.js`:** The single source of truth for grid mathematics, data validation, and compaction logic. Wrapped in a Universal Module Definition (UMD), it is consumed by both the browser UI and the Node.js backend.
*   **`editor.js`:** The browser-based Leaflet application. It handles DOM manipulation, local storage draft management, rendering, and the GitHub API integration for publishing map updates.
*   **`compact.js`:** A Node.js script executed by GitHub Actions that imports `core.js` to process the raw map data into continuous, compressed coordinate ranges.
*   **`euro-use-master-map.json`:** The comprehensive, uncompressed source dataset containing all curated dots, editor history, timestamps, and comments.
*   **`euro-use-eligibility.json`:** The lightweight, compressed output file automatically generated by GitHub Actions for consumption by Dot Safari.

## The Editing Workflow

The map editor allows curators to visually assign eligibility statuses (Conquerable, Unconquerable, Water Only, Foreign, Unreviewed) to specific geographic dots. Water Only means no land anywhere in that dot, including sea or inland water; a small island still makes it a land dot. The existing `sea` JSON key, saved maps and history remain compatible. Old written comments are retained as originally entered. The label change does not classify or detect inland lakes automatically. Unreviewed remains available for later investigations.

1.  **Local Editing:** Edits are made in the browser and automatically saved to `localStorage` as a working draft. Unfinished forms and comments are retained between sessions.
2.  **Reviewing:** Editors can generate a visual HTML Change Report summarizing their session's actions, which can be saved or shared.
3.  **Publishing:** Clicking "Publish" prompts for a GitHub Personal Access Token. The editor uses the GitHub API to push the updated `euro-use-master-map.json` directly to the `main` branch.
4.  **Automation:** The push triggers a GitHub Action (`compact-map.yml`) that runs `compact.js`, generating and committing a fresh `euro-use-eligibility.json` file.

## Worldwide classification background

Current test candidate: **1.3.0-rc2**.

The current master map contains a compact snapshot of the separate [worldwide land model](https://github.com/ShortOkapi/ebt-world-land-map), including its manual overrides. Dots without an individual classification resolve to Foreign where that model contains land and Water Only elsewhere. An explicit classification always wins, including a deliberate Unreviewed decision. This background does not add eligible Euro-use targets or remove every inland lake.

The 19 previously Unreviewed remnants reviewed by Miguel have been assigned Foreign or Water Only, with the earlier history retained. Original workbook references are preserved. Automated changes are identified in history as Automatic worldwide background.

`classificationBackground` in the master and `classifications.background` in the compact export use formatVersion 1, land ranges and a checked land count. Their source metadata records the world-land repository commit and SHA-256 hashes of its base and overrides. The remaining grid is Water Only. The editor draws ranges and Dot Safari resolves them on demand; neither needs half a million individually stored classifications. The existing grid, eligible ranges and `sea` key are unchanged.

Opening an older map without this optional background preserves its original defaults; importing that map does not silently install a new background. Save Map File and Undo/Redo preserve an explicit Unreviewed choice. Use a fresh working copy of the new master to inspect this update; restoring an older local draft may restore the old background too.

During candidate testing, use **Save Map File** to retain your work. **Publish writes to main**, regardless of the code branch being tested. Commit the candidate's prepared master and compact files to its release branch through the repository editor; use Publish for normal map maintenance after the stable version is merged.

Refreshing the pinned background is a data preparation operation: regenerate its merged ranges from the recorded world-land source and overrides, preserve individual decisions and history, increment the master revision, validate, and regenerate the compact export with core.js. Do not hand-edit thousands of background ranges. Preparation scripts stay outside this lightweight repository.

The worldwide snapshot is derived from OpenStreetMap contributors, under ODbL 1.0. It describes land/no-land according to that model; access and euro-use eligibility remain separate curated decisions.

## Dot names in the side panel

The side panel identifies the dot first, followed by its Euro-use classification. When a name is available it shows, for example, **Ourém Dot**, with **[462, 405]** on the next line. An unnamed dot is simply **Dot** followed by its ID.

The editor reads the public Dot Safari `dot-name-overrides.json` and, on demand, the relevant prepared-place block described by `data/destinations/manifest.json`. There is no second list to maintain here. Preferred names and deliberate name exclusions take precedence over automatic names. The Euro-use name is preferred; a worldwide name is used if no Euro-use name is available. Reload the editor to check updated name data.

Name lookups are optional and have a timeout. Failed lookups leave the heading as Dot and its ID; they never block editing. Only the heading is updated when a name arrives, preserving an unfinished comment or classification choice. Names are labels for orientation, separate from the eligibility decisions. They are not copied into saved maps, reports or edit history. This is name retrieval, not a name editor.

The manifest must match the existing grid; prepared blocks are checked against their recorded size and SHA-256 hash. A small in-memory cache avoids repeated downloads during the same visit. Source data remain in the Dot Safari repository: OpenStreetMap contributors (ODbL 1.0) and additional GeoNames data (CC BY 4.0), with preferred names maintained by Miguel. No Notes file or live GPS position is read or sent by this feature.

The world map repeats visually when panned far enough east or west. These copies use the same stored dot IDs and decisions. This display behaviour is explained in Help rather than repeated in the editing panel.
